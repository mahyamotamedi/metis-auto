## Sprint Day 1, Pipeline C: demo shell, lever view model (2026-11-02)

Final sprint plan (`docs/superpowers/plans/2026-11-01-final-plan.md`), task D-1. Branch `replay-scope-split-baselines` (after S-3 and E-1). **Awaiting review.** Traceability: QA-PRIV, QA-COST, FR-ACCT-05, FR-REQ-04, QA-REPRO; ADR-0024 (thin page, Streamlit-free view model), ADR-0032 (`LeverResult`, two cost blocks).

- **Built:** `src/metis_auto/wiring/lever_view.py`, a view model over `reports/levers/*.json` with no Streamlit import. `load_view` reads every `*.json` in one folder through the shared loader `LeverResult.from_json`; other files are never opened; JSON that is not a `LeverResult` is counted as skipped; no folder or no result gives an empty view with a message. `waterfall` gives baseline, saving and after-cost per block (`levers.BLOCKS`: `fees`, `token_cost`); totals are the row sums, a declared `total` that disagrees raises, and a missing block is unknown (so are the totals; never 0). The unit (recorded or repriced) comes from `compare.BASELINES`; `for_baseline` selects one baseline, so units are never mixed. `slice_rows` relabels `bot_rank:<n>` and `tenant_rank:<n>` as `bot-07` and `tenant-01` and drops any slice name outside the known forms (`all`, `llm_only`, `traffic_weighted`, `over_8k`, `lang:<label>`, the two rank forms), so no bot or user ID reaches a screen.
- **Test first:** `tests/unit/wiring/test_lever_view.py` with the plan's 4 tests (`test_view_reads_only_lever_result_json`, `test_rank_labels_not_ids`, `test_waterfall_rows_sum_to_total`, `test_empty_state_when_no_results`); first an import error, then 4 failures against a stub, then 4 passes. Fixtures are SYNTHETIC.

- **Docs:** one row in `docs/architecture/module_reference.md`.
