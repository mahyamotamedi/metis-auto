## Popular-question cache, R-A1: 24-hour TTL variant (2026-11-02)

Final-plan task R-A1 (Pipeline A), branch `sprint-saba`. Follows [phase 2](2026-11-02-popular-question-cache-r-a1-phase-2.md). Status: **awaiting review**; nothing committed. Question from the owner: production uses a 24 h TTL; did the replay model it? It did not. No model calls.

- **Finding (before the change):** no TTL, expiry or maximum age existed in `version.py`, `cache_guard.py` or `sprint.toml`; the served answer was the 90-day window's mode, so it could be up to about 90 days old. Measured on report-period hits (aggregates only): only 19.8% of first_turn hits used an answer under 24 h (median 104 h); even the key's newest answer was under 24 h for only 28.1%.
- **Decided (owner, 2026-11-02):** an optional `ttl_hours` (version `pq-v2`; `None` keeps `pq-v1` unchanged, tested). Admission is unchanged; the stored answer is the key's latest eligible answer from an earlier day; a hit counts only if that answer was logged less than `ttl_hours` before the request. Default 24 h in `scripts/run_popular_question.py` until `sprint.toml` holds `ttl_hours` (C's file: to ask C). `ttl_hours` is in the manifest's config hash; untimed runs hash as before. New lever_ids `cache.popular_question.{first_turn,all_turns}.ttl24h`; `--ttl-only` runs them without touching the untimed results or the review sheet.
- **Results (report period, candidate hits, correctness unmeasured):** `first_turn.ttl24h` 214 hits (28.1% of the untimed 762), 0.30% of the 71,979 requests that pass the EDA steps, cost share saved **0.07%** (95% CI 0.05% to 0.09%), down from 0.31%; `all_turns.ttl24h` 274 hits, 0.38%, 0.08% (0.07% to 0.10%), down from 0.37%. The untimed result overstates the saving under a 24 h TTL by about 4 to 5 times. Scope check: 0 cross-bot and 0 cross-instruction hits. The latest answer equals the window's mode for 83.1% (first_turn) and 67.4% (all_turns) of replay hits. Table: [exp-cache-002 README](../../../experiments/caching/exp-cache-002-popular-question/README.md#results-on-the-full-data-phase-2-2026-11-02).
- **Tests:** 8 new (TTL boundary strictly below 24 h, latest answer rather than mode, admission unchanged, `None` reproduces `pq-v1`, validation, lever_id and assumption, config hash, TTL source). `pytest -q` 1342 passed, 28 skipped; ruff check and format clean. The 8 new JSON files hold no Arabic script, dataset ID or grouping hash.
- **Open:** `ttl_hours` in `sprint.toml` (C); the K-1 sheet reviews untimed first_turn hits, and its stored answer is the mode, not the latest answer, so phase 3 should say which variant its correctness applies to; the TTL rule differs from ADR-0016 point 6 (entries valid until the next build plus a grace period).
