## Sprint winners in the live demo: rules-only decision router, within-message dedup, bot-level cache (2026-11-04)

Draft decision: [ADR-0066](../../adr/0066-demo-sprint-winners.md). One stage, offline, fake mode only. No live, hosted or paid call; the spend ledger and `.env` were not touched. Everything is a labelled DEMO selection, **provisional: cost only, pending quality**; serving defaults are unchanged. LLMLingua-2 was not touched.

- **Part 1, routing.** Verified that `decision_router` with `router.mode = "off"` runs end to end offline (no cascade, one fake call, no spend). New demo choices: `decision_router` (rules only) and `sticky_v1` with an `inner` of `rule_based` or `decision_router`. `RoutingConfig.candidates` (new, empty = all enabled models) is set from `config/evaluation/sprint.toml [routing] candidates` (`gpt-5-nano`, `gpt-4o-mini`, `deepseek-v4-flash`) for every non-fixed demo routing, so `gpt-4.1-nano` and `mimo-v2.5` are never chosen (tested against `catalogue-metis-test-2026-11-04-v41.toml`). The report and the UI show the tier, the reason code and a safe-tier note. The demo toggles offer only `router.mode = off`; the local, hosted and hybrid backends are unreachable from them.
- **Part 2, dedup.** `domain/context/dedup.py`: exact duplicate retrieved chunks removed inside one message, first copy kept, order stable, no pointer in the prompt, nothing else touched. Strategy `within_message_dedup` (and a `dataset_positions` variant), switch `[pipeline.context.dedup] enabled` (off by default, byte-identical to `pass_through` when off). Runs before compression. Contract schema 0.8 → 0.9 (`ContextAction.DEDUPLICATED`, `ExclusionReason.NOT_A_CANDIDATE`, span `context.dedup`, event `context_deduped`, sizes only); `contracts_reference.md` regenerated. The saving sits in the existing context term with a separate labelled sub-line (`AccountingService.dedup_effect`); fixed order and exact sum hold.
- **Overhead (the demo's own number).** `scripts/measure_overhead.py --dup-chunks 8 --dedup`, 2,000 synthetic requests, fake model, one laptop, indicative only: `context.dedup` p95 0.103 ms; whole overhead p95 2.20 ms (2.24 ms without dedup); sent input tokens 952,000 → 496,000. Files `reports/cost/overhead_demo_dedup_{off,on}.json`. The sprint's 25 ms replay figure is a different measurement and was not copied.
- **Part 3, cache.** No new cache code. Bot-level scope, "new user" and the seed work with the new settings; a hit never anchors. The key is made from the context as received (before dedup), so a request that differs only in duplicate chunks is a miss, never a wrong hit; this follows from the existing key rules, so nothing was asked. The demo has no retrieval step, so nothing was wired for the retrieval-result cache.
- **Part 4.** SYNTHETIC presets `fa_shop_dupes` and `en_faq_dupes` (duplicate chunks, a greeting, a coding-intent message, a long one); UI strings in `config/demo/ui_strings.toml` (new Persian marked `[PLACEHOLDER: Persian review]`); dedup toggle and sticky inner choice in Advanced; the cost panel shows the dedup rows next to the other savings with "Provisional: cost only, pending quality." and a line that live savings are a mechanism demo and the Results page holds the sprint figures. The 27% / 23% combined number is not shown as a live result. `docs/guides/demo_quickstart.md` §7.8, `module_reference.md` rows and `contracts.md` updated.
- **Assumptions.** Live token counts use the target model's tokenizer on the full and the sent request (fidelity shown), not ADR-0038's character coefficient, because the text is present in the demo (stated in the ADR). The dedup switch is not part of the cache key.
- **Base.** Built in a separate worktree from `origin/main` (464981f) because the local checkout was 14 commits behind with uncommitted work; nothing in the owner's checkout was changed.
