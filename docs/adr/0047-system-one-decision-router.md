# ADR-0047: System-One decision router (hosted Jev and a local open-weight model behind one port)

- Status: **draft** (R1, 2026-11-02). Points 1–11 are **decided** by the project owner on 2026-11-02 (R0 review); the thresholds, question wording and backend defaults are **provisional placeholders** until exp-route-013 gives evidence. Serving defaults do not change.
- Date: 2026-11-02
- Relates to: ADR-0003, ADR-0009, ADR-0010, ADR-0013, ADR-0015, ADR-0017, ADR-0018, ADR-0019, ADR-0020, ADR-0023, ADR-0025, ADR-0027; findings [router_r0_findings.md](../references/router_r0_findings.md); routing plan R9 and [routing.md](../architecture/routing.md).
- Traces: FR-FEAT-02, FR-ROUTE-01…07 (FR-ROUTE-04 router overhead), FR-CASC-02, FR-FAIL-04/05, FR-ACCT-03, FR-OBS-01/02/05, FR-EVAL-03/04/06/08/09, FR-DATA-02/04/06, QA-LAT, QA-COST, QA-PRIV, QA-REPL, QA-TEST; H-5, H-6.

## Context
FR-FEAT-02 left semantic intent open, and the rule-based policy (ADR-0023) has no measured signal for "does this request need the stronger tier?". A **System-One decision model** answers that kind of question without generating text: given a state (string or JSON) and named, typed questions (`choice`, `score`, `noul`), it returns one typed answer per question with probabilities, in one forward pass. The wire format (`POST …/v1/systemone {model, state, questions}` → `{model, answers, usage}`) is shared by TypeSafe's hosted **Jev** and by open-weight models (THX-01's own server, Mizan on llama.cpp), so one schema and one parser serve both.

Constraints found in R0 (findings §1–§6):
- Jev is reachable through Metis at `https://api.metisai.ir/typesafe/v1/systemone` with the Metis key (Metis page, saved 2026-11-02); only `jev-latest` is offered; the page states **no price, no rate limits, no error format**. Its latency from Iran is unmeasured.
- The dataset licence forbids sharing dataset text with third parties; the owner decided that no dataset text goes to a hosted backend until Metis confirms in writing.
- The overhead budget is 100 ms p95 (Q-14). THX-01's CPU latency is unpublished; its repository root is the English checkpoint, and its `choice:11+` calibration bucket is broken (the package clamps it).
- Every Parquet file of the full dataset is a single row group.

## Decision
1. **One port, many backends.** `ports.decision.BaseRouter` (a runtime-checkable `Protocol`, playing the role of an abstract base class, as every port here): `ref`, `kind` (`hosted` | `local`), `available()`, `decide(state, questions, *, timeout_ms)`, `estimate_cost(state_tokens)`. Backends **return** `DecisionError` for expected failures and never raise for them; no internal retries on the request path. Implementations live in `adapters/routers/`: `FakeDecisionBackend` (R1), `Thx01LocalBackend` and `SystemOneHttpBackend` (R5), `JevMetisBackend` and `LlmAsSystemOneBackend` (R6), plus recording and replay decorators.
2. **The decision model answers questions; it never picks a model.** A pure domain policy, `decision_router` (R3), maps the answers (complexity, needs-reasoning, cheap-model-ok, intent, history dependence) plus rule features and dynamic criteria (context length, latency budget, cost cap) onto a tier, a model and a reasoning effort. Unknown or failed decisions never satisfy a mapping rule (P-6): they fall through to the rule-based tier, then a configured safe tier.
3. **Cascade with fast and slow paths** (application, R4): configured gate rules decide when decisive (0 ms); then the router-result cache; then the backend chain of the configured mode under the remaining deadline, with a per-backend circuit breaker and, for hosted backends, the spend guard and the approval check; then fallback. Modes: `off` (default), `local`, `hosted`, `hybrid_local_first`, `hybrid_hosted_first`. A local mode never calls a hosted backend (validated in settings).
4. **Latency budget (owner).** The local router has its own **60 ms p95** inside the 100 ms overall overhead. Hosted Jev is for **shadow runs and labelling only**; it is never required inline. If THX-01 (multilingual) misses 60 ms p95 on the owner's Windows CPU, ONNX int8 and shorter states are tried; if it still misses, inline routing is rules only, and THX-01 and Mizan run in shadow and offline evaluation. Mizan 4B is never inline on CPU.
5. **Privacy (owner).** `DecisionState` is a content contract that never leaves memory (and git-ignored recordings): a truncated message, optionally the truncated previous user turn, and derived labels; never instructions or retrieved text. Every other decision contract is content-free and may appear in events (tested). Hosted backends receive SYNTHETIC or owner-written states only: `DecisionState.dataset_derived` states are refused unless `router.real_data_approved` (default false, **runtime layer only**) is set, and the owner keeps it false until Metis confirms in writing. Local inference on dataset text is allowed: it never leaves the machine. Local `/v1/systemone` servers must be loopback (validated).
6. **Cost and accounting.** A hosted router call's cost is a `MeasurementRecord` cost, i.e. pipeline overhead (FR-ROUTE-04, FR-ACCT-03), feeding `extra_cost` in the savings decomposition. Router prices live in their own dated file, `config/reference/prices-metis-router-2026-11-02.toml` (`reference.router_prices`), so the answering-model table keeps its version. Jev via Metis: `metis-jev-latest`, input 0.0462 USD and output 0.0000 USD per 1M tokens (Metis pricing page, checked by the owner 2026-11-02); output is priced at zero but still counted and reported. **TypeSafe's direct price is never used.** A hosted backend with no configured price is **not computed** and refused unless `router.allow_unpriced` (runtime only; stays false) is set for the run; it is never charged as zero. A `price_ref` missing from the router table is a settings error. A local router's cost is computed and zero with the new basis `CostBasis.LOCAL_COMPUTE` (no price table applies); its CPU time is reported as latency.
7. **Clients and assets.** `httpx` (already pinned in every lock; declared in the `router-local` extra since 2026-11-03, TODO-18) with strict pydantic wire models for Jev and local servers; **no `typesafe-sdk`**. THX-01 is the repository's root checkpoint, itself the multilingual (mmBERT) model (corrected 2026-11-02: there is no separate multilingual sub-model; R0 findings §5), every file it reads fetched in advance and pinned by revision and sha256 in `config/reference/routers.toml`; Hugging Face offline flags are set and any runtime download is an error. `trust_remote_code` is refused, so vLLM-SR d3 stays out. Heavy libraries are imported only in their adapter (`tests/architecture/test_router_imports.py`).
8. **Model version (owner, 2026-11-02).** Metis offers only `jev-latest`, an alias whose model changes when TypeSafe ships a release. Every `DecisionResult` records the version the response reports (`model_revision`, e.g. `jev-1.13.0`); local backends record their pinned weights revision. The router-result cache keys on the model revision, and when a backend reports a revision different from the last one seen, that backend's cached results are invalidated and the change is flagged for re-checking results (offline labels and comparisons made under the old version are marked stale) (R4, R6).
9. **Question set.** Versioned and configured in `config/reference/router-questions-v1.toml` (`routing_qs_v1`, English and Persian wording with identical IDs, types, options and levels, checked by the loader; provisional wording, Persian to be reviewed). The `intent` question has **at most 10 options** (`summarisation` merged into `writing`, `media_request` into `other`) because THX-01's calibration for 11+ options is broken; the loader refuses more. Its mapping to `analysis/prompt_labels.py` categories is in the same file (`[intent_mapping]`, approximate by design).
10. **Development data: a 150-record dev slice of the full dataset** (R2), seeded and stratified, built from Parquet (PostgreSQL is not running on the owner's machine), split by session into `tune` (~70%) and `check` (~30%); golden-v1 and golden-v2 records are excluded so golden-v2 stays the held-out test. **The pyarrow import rule is widened on purpose** (`tests/architecture/test_db_imports.py`): pyarrow may be imported in `data_access/full/` as well as `data_access/postgres/`, because the slice reader must project columns and filter rows one Parquet file at a time without a database, and `data_access` is the layer that owns dataset reading (ADR-0009). It stays out of every other package. Files are read one at a time with only the needed columns; content columns are dropped as early as possible.
11. **Configuration split.** `[router]` (settings, `settings/router.py`) holds infrastructure: mode, deadline, confidence gate, backends (a discriminated union by `type`), chains, router cache, circuit breaker and the runtime-only approvals. The routing **policy** knobs (gate rules, mapping thresholds, criteria, hysteresis, state truncation, safe tier) live under `[pipeline.routing.decision_router]` and are validated by the domain policy's own config type (configuration.md §3 rule 5), like `rule_based`. The machine-local dataset root is `[data] full_data_root`, set only in `config/local.toml` or `METIS__DATA__FULL_DATA_ROOT`, outside the config hash.
12. **Status.** The policy and every backend are demo / placeholder components under ADR-0023 rules until exp-route-013 gives evidence. `[pipeline.routing] policy = "fixed_model"` and `router.mode = "off"` stay the serving defaults; with the router off, behaviour is unchanged (R4 regression test).

## Contracts (schema 0.6 → 0.7 → 0.8)
New modules `contracts/decision.py` (questions, answers, results, errors, availability, outcomes, `RouterSummary`) and `contracts/decision_state.py` (`DecisionState`; its own module because it reads `features.Language` while `features` reads `decision`). `RequestFeatures.decision`, `RoutingDecision.router_summary`, the `decision_measured` event with circuit states and the overhead `MeasurementRecord`, the span `route.decide`, and `CostBasis.LOCAL_COMPUTE`. Details: [contracts.md §6](../architecture/contracts.md#6-changes-from-the-stage-3-vocabulary).

R3 adds `RequestFeatures.deadline_ms` (schema 0.8): a routing policy sees only features, and the latency criterion needs the request's time budget.

## Policy details (R3, provisional)

- **Undetermined requests go to the safe tier** (`undetermined = "safe_tier"`, tier 1): when no answer fires and only the rules' default matches, including when the router is off or failed. `rules_default` is the cheaper alternative, configurable.
- **Low-confidence answers** are ignored unless `use_soft_signals` is set (P-6).
- **Criteria:** a known input of at least 32,000 tokens raises the tier to at least 1; `max_tier` clamps; a request deadline at or under `fast_model_deadline_ms` prefers models with a **verified** `low_latency` capability (none in the catalogue today, so it is off by default and only reports `criteria.low_latency_unavailable` when enabled); an effective cost above `max_effective_cost_per_answer` is flagged, not forced.
- **Reasoning effort:** a hint only for models listed in `effort.models` (default `gpt-5-nano`), `minimal` when `needs_reasoning < 0.3`; expected hidden reasoning tokens per effort can be configured for ranking.
- **Sticky hysteresis is stateless** (P-8): earlier turns carry no decision answers, so "low-complexity turn" is a proxy from cheap turn features (no code, no coding intent, length bucket ≤ 1) (A-96). A fallback decision never moves an anchored session.
- `route()` now selects a tier's cheapest model itself when a policy answers with a tier (`_cheapest_in_tier`, previously `NotImplementedError`).

## Cascade details (R4, provisional)

- `application/routing/`: `RouterCascade` (gate → state → router cache → backend chain → confidence gate), `RouterResultCache` (keyed fingerprint of the folded state, question set, backend, model revision; a new revision drops that backend's entries and is recorded), `CircuitBreaker` (closed, open, half open, per backend). Built by `wiring.routers` from `[router]` only when `router.mode` is not `off`; the pipeline is unchanged without it (byte-identical regression test against digests captured before R4).
- **Feature set:** `fs-0.4.0-router` only when the router fills `RequestFeatures.decision`; `fs-0.3.0-demo` otherwise. The decision step runs inside the features stage, before `features_extracted`, so that event carries the decision the policy sees.
- **Run-level provenance (A-102):** a run's states are dataset-derived unless its caller declares SYNTHETIC or owner-written text, so hosted backends refuse them by default.
- **Low confidence (A-103, owner 2026-11-02):** by default it ends the chain (`failed(low_confidence)`, routing falls back); `[router] escalate_on_low_confidence = true` asks the next backend while time and budget remain (low-confidence answers are then never cached). R8 compares both.
- **Hosted accounting (A-104):** the router has its own `SpendGuard` over the shared capped ledger. A hosted answer charges its actual cost; a hosted error charges the pre-call estimate and stops hosted router calls for the run (ADR-0021's rule); an unpriced call (only with `allow_unpriced`) charges nothing it cannot compute, is recorded as not computed, and stops the guard after that call.
- **Confidence (A-105, owner 2026-11-02):** the gate uses the lowest backend-reported confidence over the answers; a backend that reports none is not gated (no number is invented), and a missing confidence never satisfies the tier-0 rule's `tau_conf` (P-6, tested).
- **Backends in R4:** `fake` only (profiles `neutral`, `cheap`, `complex`); a chain naming THX-01, a local server, Jev or the LLM backup is refused with the phase that adds it (R5, R6).
- **Slice replay:** `scripts/replay_router_slice.py` replays the frozen 150-record slice with the fake answering client and fake backends (`off`, `local` with two passes, `hosted_refused`), checking first that the local records are the committed slice; it prints counts, timings and peak memory only.

## Local backends (R5, provisional)

- **Pins made on the owner's machine.** The project's own network cannot reach the Hugging Face Hub, so `config/reference/routers.toml` ships **unpinned** and `scripts/fetch_router_assets.py` pins it there: `plan` (Hub metadata only: commit, files, sizes; lists only the folders the asset names, never the repository's demo and training folders; a Hub error prints the URL and HTTP status; refuses a checkpoint missing a required file), then `pin --yes`, which downloads at that commit and verifies every file against the Hub's own tree at that commit (LFS sha256, or git blob ID for small files) before recording its sha256 (A-106). Each file is retried up to five times and a dropped download resumes with an HTTP range request; verified files survive a failed run, so re-running `pin` continues. This is stronger than the compressor table's trust-on-first-download for small files. An unpinned asset is never loaded.
- **THX-01 in process** (`adapters/routers/thx01_local.py`, extra `router-local`): sha256 of every pinned file checked at load; Hugging Face libraries offline; loaded from a **work directory** where only the files up to 1 MiB are copied (`thx01`'s `_fix_tokenizer_config` may rewrite `tokenizer/tokenizer_config.json`, which would break the pin) and every large file is hard-linked to the pinned one (symlinked if hard links are refused, otherwise refused): the weights are never duplicated (A-107, owner 2026-11-02); stdout and warnings contained; a clamped calibration bucket marks the backend uncalibrated; loaded when the pipeline is built, never on the request path.
- **State rendering** (`adapters/routers/wire.py`): compact text by default (`Previous user message: …`, `Message: …`, a line of derived labels), `json` as an option; one shared wire shape for THX-01 and `/v1/systemone` servers (A-108).
- **Local server** (`adapters/routers/systemone_http.py`, `httpx`): loopback only; health checked at most every 5 s; failures returned with an HTTP code, never a body; reports itself uncalibrated (Mizan's calibration under llama-server is undocumented).
- **Lock** `requirements-router-local.lock`: the dev lock plus the extra, shared pins equal to the compress lock, thx01 1.0.0 by PyPI's published sha256; resolved on Linux with torch's Linux-only CUDA dependencies removed, so it serves Windows and macOS like the compress lock (A-109).
- **Benchmark** `scripts/measure_router_overhead.py`: one backend in isolation on synthetic or frozen-slice states built as the cascade builds them; p50 to max overall and by message length, share over 60 ms, model input tokens, confidence-gate share. THX-01 encodes one sequence per question (five per request), so CPU latency scales with questions × state length.

## Hosted backends, chat toggles and evaluation (R6–R8, provisional; owner pre-approval 2026-11-03)

- **Jev via Metis** (`adapters/routers/jev_metis.py`, `httpx`, declared in the `router-local` extra since TODO-18): `POST <base_url>/v1/systemone` with the Metis key as a Bearer header; `base_url` is in `[router.backends.jev_metis]`, not in `endpoints-metis.toml` (Jev is not OpenAI-compatible; A-112). Cost and the pre-call estimate come from the router price table (`metis-jev-latest`); the estimate counts the questions' text at 2 characters per token, an upper bound. No key = unavailable. Jev is a System-One model, never a routing target (A-111; [jev_model_note.md](../references/jev_model_note.md)).
- **LLM-as-System-One backup** (`adapters/routers/llm_system_one.py`): a chat model asked the same questions for a JSON reply through the live `ModelClient` (the SDK stays in `openai_compat.py`); cost and estimate injected by wiring from the catalogue's price row (adapters import only ports and contracts); uncalibrated (A-113).
- **Live check** (`scripts/router_live_check.py`, J-4 remapped): one SYNTHETIC state to Jev, the backup on three test models, and a strict `json_schema` probe; plan first (calls dropped until the total fits 0.05 USD), each call under its own spend guard over the persistent ledger (A-116); without `METIS_API_KEY` it skips and says so.
- **Confidence gate (Q-61, owner 2026-11-03):** the lowest confidence among the **mapping questions** (complexity, needs_reasoning, cheap_model_ok) by default; `[router] confidence_questions = "all"` restores every answer.
- **Chat and UI (R7):** `RoutingMode.DECISION_ROUTER` with a `router_mode` (off, local, hosted, hybrids) in `wiring.chat`, `scripts/chat.py --mode decision_router --router-mode local`, and a radio entry plus a backend selector in the Demo B page; `METIS__ROUTER__MODE` (with the chain's `…__ENABLED`) switches it from the environment. Typed chat text is not dataset-derived; the seeded sample is. Serving defaults unchanged (`router.mode = "off"`, `fixed_model`).
- **Evaluation (R8, exp-route-013):** a shadow comparison of rules only and the router on the frozen slice (`wiring/router_eval.py`, `evaluation/router_eval/`), per split, balanced and traffic-weighted, Persian first; L4 synthetic labels in CI; the routing step version on R-0's routing base (A-115). L1 and L3 paths prepared, not run.
- **Mizan:** skipped (2.7 GB, CPU latency), future work (A-117).

## Results of the owner's runs and what they decided (2026-11-03, provisional)

- **Jev via Metis works** (`jev-latest` reported `jev-1.14.0`; 699 input / 171 output tokens; 0.0000322938 USD, input only) but took **3.5 s**: never inline. The estimate was revised upward after this call billed more than it had estimated ([jev_model_note.md](../references/jev_model_note.md)).
- **THX-01 on the owner's 4-core CPU:** p50 about 4 s, p95 6–12 s, load about 2.5 min, 2.3 GB. **Inline routing is rules only** (the owner's pre-approved rule; `router.mode` stays `off`). THX-01 runs in shadow and offline evaluation, and ONNX is future work (A-118). Loading now checks for float32 weights, and calls run under `inference_mode`.
- **The inline shadow run compared the rules with themselves.** The 60 ms deadline timed THX-01 out and the breaker opened, so every request fell back to the rules. The evaluation therefore has an **offline mode** (60 s per request, no cache, gate off), which also reports per-question confidence and probability distributions.
- **Gate:** `[router] confidence_statistic` (`reported` or `probability`) next to `confidence_questions`. The provisional threshold is fitted on the tune split and checked on the check split (A-119).
- **Backup model:** `gpt-4o-mini`, because Metis no longer serves `gpt-4.1-nano` (HTTP 404, TODO-17).
- **Offline shadow result:** THX-01 answered 82.7% of the slice and **changed no routing decision** (agreement 1.0 with the rules, every split, view and language). Its yes/no answers sit near 0.5, so the safe tier decides. There is no saving over the rules on the slice. The router stays a **measured, shadow-only component** until labels (L1) show where it is right (A-121). The profiled latency is inherent on this CPU: the weights are already float32, and one batched pass takes 3.3–4.8 s (A-118).
- **Live:** `mimo-v2.5` is refused in every shape and `gpt-4.1-nano` returns 404, so both are to be disabled by the catalogue's owner (Q-42, TODO-17). Tier 0 then holds only `gpt-5-nano` (A-123). `response_format: json_schema` returns HTTP 400 on the OpenAI wrapper; the backup keeps prompt-and-parse (A-122). Total live spend 0.0016 USD (A-124).
- **Synthetic decision-quality check (jev-synth-v1, 2026-11-03; [exp-route-013](../../experiments/routing/exp-route-013-decision-router/README.md#synthetic-decision-quality-check-jev-synth-v1-2026-11-03)).** 100 SYNTHETIC requests (70 Persian, 15 English, 15 mixed) with the owner's tier labels (60 tier 0 / 40 tier 1), through the real pipeline; THX-01 and Jev asked on every row (gate off, offline settings).
  - **Tier accuracy:** Jev **72%** (95% interval about 63–80%), the plain rule-based policy 59%, the rules path (router off) 43%, THX-01 41%. Always-tier-0 would score 60% on this set, so only Jev is above both trivial baselines, and only just.
  - **By language,** Jev scored 69% on Persian, 87% on English and 73% on mixed.
  - **Jev's errors are on the cost side:** it sent 1 of 40 hard requests to tier 0 and 27 easy ones to tier 1. THX-01 sent 1 of 60 easy requests to tier 0 (`cheap_model_ok` p50 0.59 < `tau_ok` 0.7). Where Jev's own answers decided (85 rows), it was right on 85%.
  - **Cost and latency:** Jev cost 0.0032 USD for 100 calls; p50 0.97 s, about 10× the overhead budget, so **still never inline**.
  - **Limits:** synthetic requests, one rater, n = 100. **A first signal, not proof.** Quality on real traffic stays unproven until Metis allows dataset text (Q-55) and labels exist (L1, the paid benchmark). The set is an evaluation set: no threshold is tuned on it.
  - **What it changes:** nothing in serving (`router.mode` stays `off`). It is the case for asking Q-55, and Jev's shadow role (Mode 1) is now the stronger candidate for labelling (A-125).

## Alternatives considered
- **RouteLLM router weights.** Trained on other domains and English chat; poor transfer to short Persian follow-ups. Rejected; RouteLLM's threshold calibration and APGR/CPT metrics are adopted instead (exp-route-013).
- **Arch-Router and similar generative routers.** Generate a route name token by token (slower), English-centred, and pick models directly, coupling the router to the catalogue. Rejected.
- **Clef / Clef-flash.** GPU only. Rejected for the owner's CPU machine.
- **Laya out of the box.** 62.4% mean on 3,000 Persian records (Mizan card, self-reported; the owner's earlier research reports 27.2% on Persian intent, unverified here). Usable only as a fine-tuning base. Rejected for now.
- **An LLM-as-router only** (a chat model returning JSON). Slow, uncalibrated, and every call is a paid hosted call with dataset text. Kept only as Jev's backup on SYNTHETIC text.
- **Jev inline only.** Unverified latency from Iran, no published Metis price, and the licence keeps dataset text off hosted backends. Kept as shadow and labelling backend.
- **vLLM-SR d3-edge / d3-lite.** Needs `trust_remote_code`; refused by the owner.
- **A decision model choosing the model directly.** Couples the model to the catalogue and makes every catalogue change a retraining question. Rejected: the policy maps answers to tiers.

## Consequences
- The decision router is replaceable per backend by configuration (QA-REPL) and testable offline with the fake backend (QA-TEST).
- Router latency and cost are measured and attributed as overhead (FR-ROUTE-04); a failed or slow router degrades to the rules, never blocks a request.
- Schema 0.7: events now carry `decision` and `router_summary` (null when unused); data written under 0.6 is not guaranteed readable (contracts.md §2.7).
- New runtime-only keys tighten the loader's layer rules; `data` joins the sections an experiment may not set.
- Integration with R-0 (ADR-0045): offline through exp-route-013's routing step version, which uses `candidate_costs` unchanged; the serving path keeps the serving eligibility filter (ADR-0045's own decision; layer rules forbid `domain`/`application` importing `analysis`).
- Open: Metis rate limits and error format for Jev (the price is now a dated row, A-92 resolved); Jev latency from the owner's network; THX-01's CPU latency and Persian accuracy on real slice states (R5); whether llama-server applies Mizan's calibration (R5); the Windows lock gap (TODO-16).
