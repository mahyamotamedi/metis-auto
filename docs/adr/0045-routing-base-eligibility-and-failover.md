# ADR-0045: The routing base promotes B's interim eligibility rules, excludes every unknown, avoids long-context price tiers, and replays candidate cost by the baselines' pricing rule

- Status: **decided** by the project owner, 2026-11-03 (Pipeline C, sprint task R-0, taken over from Parham with his agreement), points 1 to 6. Point 7 (unknown attachment count) is the agent's reading of point 4, **provisional** until the owner reviews it.
- Date: 2026-11-03
- Relates to: [ADR-0036](0036-replay-scope-split-and-baselines.md) (split, baselines, price-file units, "unknown is never zero"), [ADR-0041](0041-replay-pricing-for-logged-models.md) (replay catalogue and price table for logged models; tier and equivalence-group placeholders); FR-ROUTE-01, FR-ROUTE-05, FR-FAIL-01, FR-FAIL-02, FR-FAIL-03, FR-FAIL-04; A-48; sprint plan R-0, Shared interfaces (`eligible_models`, `failover`), Review Focus 3; consumers R-A3, R-B3, R-C3, J-3.
- Code: `src/metis_auto/analysis/routing_base.py` (`eligible_models`, `eligibility_frame`, `candidate_costs`, `failover`, `candidate_list`), `baselines_full.model_row_costs` (additive), `scripts/routing_base_report.py`; tests `tests/unit/analysis/test_routing_base.py`.

## Context
Three routing versions (R-A3, R-B3, R-C3) and the JEV run (J-3) need the same answer to "which cheaper model may serve this request". On 2026-11-02 no shared routing base existed, so Pipeline B wrote an interim rule set inside its experiment (EXP-ROUTE-011 `eligibility_interim.py`), labelled interim and excluded from final comparisons. The catalogue verifies no image, file or tool capability, so FR-ROUTE-05 ("unverified counts as unsupported") decides those requests. Some price rows are context tiers (`min_input_tokens` / `max_input_tokens`), so a cheap model can become dear on a long request. The catalogue's `tier` and `equivalence_group` are placeholders (A-48; ADR-0041 for the replay-only rows), not measured capability. Repricing must follow the cached-token convention of `baselines_full` (Review Focus 3), or candidate costs and baselines would not be comparable.

## Decision
1. **Rule set = B's interim rules, unchanged in meaning** (FR-ROUTE-01, FR-ROUTE-05). A candidate is eligible for a request only if it is in `sprint.toml [routing] candidates` (plus `candidates_jev`), enabled in the catalogue, not retiring, priced, has a known `context_window` and `max_output_tokens`, and effective input plus logged output fits the window and the output fits the limit. Requests with attachments or from bots with configured functions get no candidate. A retiring candidate is replaced in place by its configured `replacement`, which must pass the same rules. The module docstring gives each rule a one-line rationale and the order in which a request's first failing reason is reported.
2. **Vision:** no catalogue model has a verified vision capability, so a request with image attachments has no eligible candidate and stays on its incumbent. The routing base never marks a model vision-capable; a verified capability in the catalogue would need a new decision.
3. **Long-context price cliff:** `sprint.toml [routing] avoid_long_context_tier = true` (required, no default in code). When true, a candidate is excluded if the request's effective input falls into one of its price rows with `min_input_tokens > 0`. No candidate has such a tier in `prices-metis-2026-10-18-logged`, so the rule is inert today; it matters once a tiered model becomes a candidate.
4. **Unknown is never eligible:** an unknown limit, an unknown price (no price row, or no row covering this input), unknown tokens, or an unknown attachment or function count excludes the candidate, and the reason is recorded.
5. **API** (pure pandas in `analysis`, imports only `analysis.baselines_full` and `analysis.levers`): `eligible_models(row, catalogue, prices, rules) -> tuple[str, ...]` exactly as the plan's shared interface; `eligibility_frame(req, ctx, *, rules, cached_separately)` (one bool column per candidate plus `first_failing_reason`, row-by-row equal to `eligible_models`, tested); `failover(model, catalogue, *, retiring) -> tuple[str, ...]`: the same model on another provider (none exists today), then other enabled models of the same `equivalence_group`, then enabled models one `tier` up; never the model itself, a disabled or a retiring one. `retiring` is a required keyword (an addition to the plan's `failover(model)`), so a retiring model cannot slip in by default. FR-FAIL-03 holds: groups come from the catalogue, never from labels.
6. **Candidate cost replay** (free): `candidate_costs(req, ctx, candidates, *, rules, cached_separately)` gives each row's price-file cost per candidate, NaN where it is not eligible, through `baselines_full.model_row_costs` (cached tokens added back for the logged models that report them separately; tier chosen by effective input). Its sums equal `baselines_full`'s repricing of the same rows (tested). `baselines_full` gained this one public helper; no existing behaviour changed.
7. **Unknown attachment count (provisional, agent):** the only difference in meaning from B's interim file. B treats a missing `u_att_n` as no attachment; point 4 and the R-C1 rule ("unknown counts as attachments") exclude it. On the tune split this removes 1,162 of 209,331 LLM rows from routing (`reports/routing/routing-base/tune_eligibility.json`).

## Alternatives considered
- **Reuse `domain/routing/eligibility.filter_eligible`** (the serving filter, pydantic contracts, a context safety margin). It works on one `RequestFeatures` at a time and needs modality detail the logs lack; replays over 200k rows need a vectorised pandas path. The rules agree in spirit (unknown window excluded, unverified capability unsupported); the serving filter stays the serving path.
- **Keep B's interim file and let each pipeline copy it.** Three copies would drift, and R-B3's results would stay out of the final comparison.
- **Treat a missing attachment count as no attachment** (B's choice). It routes requests whose attachments are unknown, against point 4.
- **Price the long-context tier instead of excluding it.** Possible later (set `avoid_long_context_tier = false`); the owner chose avoidance, so a router never picks a model whose price jumps on that request.
- **Failover without the tier-up step** (FR-FAIL-02 keeps the tier). The plan's interface includes "one tier up"; that step is escalation in FR-FAIL-02's terms, and callers record it as escalation, not failover.

## Consequences
- R-A3, R-B3, R-C3 and J-3 import one function. B's switch-over: replace the injected `interim_eligible_models` with `analysis.routing_base.eligible_models`, and pass `sprint.toml [routing]` as `rules` (it now carries `avoid_long_context_tier`).
- Tune split, LLM rows: 202,610 of 209,331 (96.8%) have at least one eligible candidate; first failing reasons: attachments 2,676, functions 2,277, unknown attachment count 1,262, unknown tokens 506 (the same 506 as R-B3).
- Fit and cost assume model-independent token counts (a *simulation*). Per-candidate Persian tokenisation (plan R-0 "also tokenize") is not done: a follow-up.
- `tier` and `equivalence_group` stay placeholders (A-48); the failover chain is only as good as they are. No provider has a second route to the same model today, so the first failover step is always empty.
- FR-FAIL-04 (bounded retries, every attempt recorded) belongs to the serving path; this module only orders the chain.
