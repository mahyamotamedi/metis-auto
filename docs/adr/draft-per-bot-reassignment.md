## Context

The plan's routing decision rule compares every router with **per-bot reassignment** ("keep a more complex router only if it beats per-bot reassignment outside the confidence interval"), so R-A3 is the reference the other routing versions are measured against. No quality labels exist (P-1..P-3 have not run), so R-A3 can only simulate cost, and no bot may be declared moved. Historical model choice is bot configuration, not a label (EDA §4.4).

The EDA's routing simulation (14.2% of recorded cost for its rule group, 41.6% for all billed requests) is a hypothetical upper bound. It sends every request to one target (`gemini-2.5-flash-lite`) at implied recorded rates, with no eligibility check. R-A3 reproduces it exactly first (14.1677% and 41.6330%; it needs the EDA frame's cached-token add-back), so later figures can be set against it.

A first R-A3 run (2026-11-03 morning) used B's interim eligibility before R-0 existed. It reported 74.0% of `todays_models` cost, all of it from moving bots to `gpt-5-nano` and `mimo-v2.5`, which bill hidden reasoning as output (ADR-0046 point 4). Its savings against `premium_gpt_5_5` and `best_single_cheap` were "baseline minus routed pipeline cost". That figure includes the gap between the baselines (98.3% and −58.5%), so it was not the router's effect. R-0 then landed (ADR-0045), and R-C3 fixed per-baseline accounting (ADR-0046 points 5 and 6).

## Decision

1. **Unit of decision: the bot.** Fitted on tune rows (`split_by_session` tune and `period` tune, as R-C3; LLM requests). Each bot gets one **target**: the candidate R-0 allows for **every** priced tune request of the bot, with the lowest summed list-price cost there (ties alphabetical). Bots under `[sufficiency] min_n` tune requests, bots whose logged model has no price, and bots with no such candidate get no target and keep their model.
2. **Strict bot eligibility (owner, 2026-11-03, after seeing its effect).** "Every priced tune request" includes requests whose attachment count is unknown, which R-0 treats as ineligible (FR-ROUTE-05: unverified counts as unsupported). A few such requests rule out a whole bot. This removes the five costliest report bots (81% of `todays_models` cost) and is accepted: the reassignment must hold for all of a bot's traffic.
3. **Eligibility and cost from R-0, injected.** `routing_base.eligible_models` (the version's `constraints`) and `candidate_costs` (its `costs`), with `sprint.toml [routing]` as `rules`. The version drops `rules["candidates_jev"]` and uses its constructor `candidates`, so J-3 runs the same code with its own list. No eligibility rule is copied into the version. `no_eligible_why` only asks the injected function again with one cause removed.
4. **Two candidate sets** (ADR-0046 point 4). The primary result `route.per_bot` excludes candidates the catalogue marks `hidden_reasoning_billed_as_output`. The secondary `route.per_bot.with_reasoning_models` includes them, labelled "lower bound on candidate cost, hidden reasoning not counted".
5. **Four baselines, each in its own units** (ADR-0036, ADR-0046 point 5). Repriced baselines use list prices through `baselines_full` (cached tokens added back for the logged models that report them separately, Review Focus 3). `as_logged` uses the recorded token cost against the target at implied recorded rates (`reports/full_eda/tables/implied_unit_rates.csv`, the ADR-0038 pattern). A needed rate that is missing makes the request's saving unknown (out of both sides, counted), never 0. Requests not moved save exactly 0. Fees never change.
6. **Incumbent per baseline (provisional, ADR-0046 point 6; Q-B21).** In each baseline the incumbent is that baseline's model: the logged model for `todays_models` and `as_logged`, the premium model, or the best single cheap model. A bot is reassigned in a baseline only if its target's tune cost is strictly lower than that model's, in that baseline's units. A request then moves only if the target is eligible for it, is another model and is strictly cheaper on it. Every saving is the router's own effect and is >= 0 row by row. `apply` returns the `todays_models` decision; `baseline_frames` does the per-baseline accounting outside `apply`. On a [SYNTHETIC] frame where both move the same rows, it gives the same `todays_models` and `as_logged` saving as R-C3's (tested).
7. **Labels.** Evidence class `simulation`, `correctness_state` `unmeasured`, the assumption "quality not proven; cost simulation only"; slice keys count requests as "switched", never "moved"; per-bot tables carry rank labels, never IDs.

## Alternatives considered

- **Per-request routing** (the EDA, R-C3): a different lever. R-A3 is the plan's per-bot reference.
- **Bot eligibility on a share of tune requests, or on the requests R-0 can judge** (unknown attachment counts aside), with ineligible requests keeping their model: it would keep the large bots in the simulation. Rejected by the owner (point 2), because a bot-level reassignment that fails on part of the traffic is not one.
- **One routing decision priced against every baseline** (R-B3's reading, ADR-0048 point 6, and R-A3's first run): it mixes the gap between baselines into the saving. Replaced by point 6, which the owner may overturn (Q-B21).
- **No `as_logged` routing result** (the first run, ADR-0036's price-file rule for routing): it left only list-price figures, which overstate the saving where the price file is far above recorded rates (`gemini-2.5-flash`: 0.33 / 2.75 per M against implied 0.16 / 0.87). Replaced by point 5.
- **B's interim eligibility**: superseded by R-0 (ADR-0045).

## Consequences

- Results (report split, 20,750 LLM requests). Primary: `todays_models` 6.28% (5.03% to 7.49%), `premium_gpt_5_5` 8.17%, `best_single_cheap` 0%, `as_logged` 4.00% (3.65% to 4.41%; 115 requests unknown, because `gpt-4.1-nano` has no implied cached rate). With reasoning models: 7.12%, 8.23%, 0.002%, 3.85%. All primary savings go to `gpt-4.1-nano`. Quality not proven.
- The EDA's 41.6% and 14.2% stay upper bounds. They share R-A3's unit and pricing method but not its population, target, eligibility or decision unit.
- R-A3 and R-C3 are comparable per baseline. R-B3 uses the other meaning (ADR-0048 point 6, which names both and leaves the choice for I-2), so it is comparable with R-A3 only on `todays_models`, and only after one meaning is chosen for all three (Q-B21).
- Bots with configured functions, or with any attachment (known or unknown) in tune, never get a target until R-0 verifies capabilities. Adding priced Gemini rows to the candidates needs R-0 to separate "priced for replay" from "callable" (open).
- Overhead (L-1, offline per-request estimate): p95 54.2 ms primary, 51.5 ms with reasoning models, after `apply` was changed to price only the targets present (same math, tested equal).
