# ADR-0043: A Gemini adapter on the standard library, offline until a live check

- Status: **decided** (adapter shape, no SDK, no dependency, explicit thinking budget, wiring by `api_format`); wire-format field names **provisional and unverified** (no Gemini response has been seen through the Metis wrapper); the endpoint stays `deferred`. Decided by the lead (Mahya), 2026-11-02, plan stretch item 1.
- Date: 2026-11-02
- Traces: FR-API-02 (adapters normalise request, response, usage, finish reasons, and errors), FR-FAIL-01 (error classes the attempt policy retries or fails over on), QA-REPL (a provider is one interface implementation plus one config entry).
- Relates to: ADR-0003 (offline by default), ADR-0013 (no hidden attempts), ADR-0018 point 2 (Gemini deferred; amended by [ADR-0042](0042-gemini-live-calls.md)), ADR-0019 (configuration and secrets), ADR-0020 (token inclusion rules), ADR-0021 (the OpenAI-compatible adapter, whose pattern this follows).

## Context

The Metis wrapper serves Gemini at `https://api.metisai.ir` in Google's `google-genai` format, not OpenAI-compatible, with the key in an `x-goog-api-key` header and the example path `/v1beta/models/<model>:generateContent` ([metis_wrapper_api.md](../references/metis_wrapper_api.md) §1, Metis page saved 2026-10-18). ADR-0018 point 2 deferred Gemini because it needs a second adapter. Gemini labels are a large share of the logged traffic (they are unmapped in `label-mapping-full-v1.toml`), so being able to call Gemini matters for counterfactual answers. The task must not wait on any teammate: no dependency, no change to `pyproject.toml` or any lock, and no live call.

What could be verified on 2026-11-02: the base URL, path, header, and format (above). What could **not** be verified: every JSON field name of the request and the response. The Metis page shows only the SDK, and no recorded Gemini response is in the repository. Two conventions matter for token accounting (ADR-0020 §3.1, the cached-token convention of Review Focus 3): whether `promptTokenCount` already includes cached tokens, and whether `candidatesTokenCount` already includes thinking tokens. Neither is documented in the repository.

## Decision

1. **New adapter `adapters/providers/gemini_native.py`, implementing `ModelClient` (source `live`), with no SDK.** The wrapper's Gemini endpoint is plain HTTPS + JSON, so the adapter uses only the standard library (`urllib.request`, `json`) behind a small injectable `Transport` callable (`HttpRequest` in; status, headers, and body out; `TransportError` with kind `timeout` or `connection` when there is no response). The default is `urllib_transport`; tests inject a fake and monkeypatch `urlopen` to raise. Architecture tests (`tests/architecture/test_live_sdk_imports.py`) enforce three things: `urllib.request` and `http.client` are imported only here (plus the pre-existing Hugging Face token check in `wiring/db_ingest.py`); no Gemini SDK or undeclared HTTP client (`google`, `httpx`, `requests`, `aiohttp`, `urllib3`) is imported anywhere; and the providers package does not import the module eagerly.
2. **No dependency.** Nothing is added to `pyproject.toml`, any `requirements*.lock`, or `constraints-min-age.txt`.
3. **Normalisation into the existing contracts, as in ADR-0021.**
   - Usage (`usageMetadata`; field names expected, UNVERIFIED): `input` = `promptTokenCount`. When `cachedContentTokenCount` is > 0, the result depends on `PROMPT_COUNT_INCLUDES_CACHED`. It ships as `None` (unknown), so that usage is **unknown** (None, logged) rather than a guess. A reported 0 stays 0, and a missing field stays None. `output` includes thinking. Whether `candidatesTokenCount` already contains `thoughtsTokenCount` is decided per response from `totalTokenCount` (the same test as `openai_compat`). When that is undecidable, output, total, and reasoning are unknown: `TokenUsage` holds reasoning as part of output. Fidelity is `provider_reported`, and `TokenCount.method` names the field(s) used.
   - Finish reason: `STOP` → `complete`; `MAX_TOKENS` → `length`; `SAFETY`, `RECITATION`, `BLOCKLIST`, `PROHIBITED_CONTENT`, `SPII` → `content_filter`; anything else → `other`. A response with no candidate and a `promptFeedback.blockReason` is a `content_filtered` error (not retryable); with no candidate and no reason, it is `unknown`.
   - Errors: the same nine classes and retryable defaults as `openai_compat`, from the HTTP status and the error body's `status` identifier, never its message. 429 → `rate_limited`; 401, 403 → `auth`; **402 → `auth`**, because the existing classes have no budget or payment class, with `payment_required` recorded in the code; 408, 504, `DEADLINE_EXCEEDED` → `timeout`; other 4xx → `invalid_request`; 5xx → `unavailable`; transport timeout → `timeout`; no connection → `connection`; a non-JSON 200 → `unknown`. **No automatic retries:** one request per invoke.
   - Message layout (A-55 adapted): instructions and each retrieved item are, in order, the parts of the one `systemInstruction`. History and the message are `contents` with roles `user` and `model`. Parts marked `thought` are not answer text.
4. **Thinking is never left to the provider.** Every call sends `generationConfig.thinkingConfig.thinkingBudget` (expected name, UNVERIFIED) from `[model_options."<model>"] thinking_budget` (a new `ModelRequestOptions` field: an integer ≥ 0, so no provider-chosen "dynamic" budget). The default is unset, and the adapter then **refuses to call** (a configuration error raised before any request), so no call can think silently. The option is allowed only for models whose endpoint has `api_format = "google_genai"`. That rule lives in `wiring.live.request_options`, so `endpoints-metis.toml` and its version (and every config hash) are unchanged. While unset, the field is left out of dumps, so existing config hashes stay the same. **Thinking tokens bill as output** (ADR-0020 §3.1); the check's estimate adds the budget to the output limit.
5. **Tests use the fake transport only** (no network, no key) and run in the normal `.venv` and CI: `tests/unit/adapters/test_adapters_gemini_native.py`, `test_adapters_dispatch.py`, `tests/unit/settings/test_settings_gemini.py`, `tests/integration/test_live_wiring_gemini.py`, `test_gemini_check.py`.
6. **Wiring by `api_format`.** `wiring.live.build_live_client` adds the native client for every *enabled* `google_genai` endpoint. A small `adapters/providers/dispatch.py` (`ModelDispatchClient`) sends each catalogue model to its client, so one recording decorator and one spend guard still see one `live` client. With no such endpoint (today), the stack is exactly as before. The `gemini` endpoint row stays **`deferred`** and the catalogue has **no Gemini row**. Enabling either is a separate, owner-approved step after a live smoke test.
7. **A live check, written and not run:** `scripts/live_gemini_check.py` (logic in `wiring/gemini_check.py`, live half reused from `wiring/wrapper_check.py`). One SYNTHETIC message to one model; the printed pre-call estimate comes first; one attempt; output cap 64 tokens; run cap 0.01 USD (also set as `[budget] run_cap`); the persistent ledger; an explicit `--thinking-budget`. It refuses while any precondition fails. Its docstring lists what it needs: the ADR-0018 amendment, a raised Metis dashboard limit, and per-run owner approval.

## Alternatives considered

- **The `google-genai` SDK** (what the Metis page shows). It is maintained by Google and would track format changes. **Rejected for now:** it needs a new optional extra and lock in the shared `pyproject.toml`, which would make this task wait on the team. Revisiting it is a separate decision.
- **`httpx` (or `httpx2`, which the `openai` SDK brings in).** Rejected: it is not a declared dependency of its own here; relying on a transitive one is fragile, and `urllib` is enough for one synchronous POST.
- **Leave the thinking budget to the provider when unset.** Rejected: thinking bills as output, and the default differs per model, so an unset budget could spend silently.
- **Assume the documented Google conventions for cached and thinking tokens.** Rejected: unverified through the wrapper; an assumed convention would misstate costs. The cached convention is a one-line constant, set once a live check shows it.
- **Add the option to the endpoint row's `request_options`.** Rejected for now: it changes a shared reference file and its version ID, so every config hash would change for a deferred row.

## Consequences

- Gemini becomes callable through configuration alone, once the owner enables it (QA-REPL: one implementation, one config entry).
- Until a live check, every field name is an expectation. If one is wrong, the adapter reports unknown usage or an `unknown` error rather than a wrong number; the check's content-free JSON shows which.
- A small live check (short messages) will not trigger implicit caching, so `PROMPT_COUNT_INCLUDES_CACHED` may stay unknown after it. Until then, Gemini responses with cached tokens have unknown usage, and accounting counts locally with labelled fidelity.
- The spend guard's own pre-call estimate in the pipeline still reserves only the generation limit. The check's plan adds the thinking budget, and the run cap bounds the actual charge.
- Re-verification: every UNVERIFIED name in `gemini_native.py`, the two conventions, and whether `maxOutputTokens` bounds thinking tokens, by the first approved run of `scripts/live_gemini_check.py`.
