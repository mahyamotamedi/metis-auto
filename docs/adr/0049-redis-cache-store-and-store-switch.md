## Context
The plan's services track adds Redis, Postgres and MLflow "behind existing interfaces", so the pipeline does not change when a store does (QA-REPL). The answer cache already has a port, `ports.cache.CacheStore` (`get(key: Fingerprint)`, `put(entry)`), and one in-memory adapter. The port passes only the key fingerprint to `get`, not the key schema version. `CacheEntry` holds content (the answer) and has a contract JSON form. The `redis` package is not installed by default: it belongs to the planned `services` extra and lock (T-0, Parham), which do not exist yet, and nor does a pytest `services` marker; `pyproject.toml` turns an unregistered marker into an error.

## Decision
1. **Same port, no rules in the store.** `RedisCacheStore(client: RedisLike, *, namespace: str)` implements `CacheStore` unchanged. It stores one value per key fingerprint, serialised with `CacheEntry`'s contract JSON (`model_dump_json` / `model_validate_json`). It sets no TTL and no Redis expiry and checks no status, scope or age: the cache policy decides validity (ADR-0011 point 5). `RedisLike` is a small protocol (`get`, `set`) that `redis.Redis` satisfies; tests use a fake.
2. **Keys namespaced by the cache key schema version.** A key is `<key_version>|<prefix>|<fingerprint>`; `redis_namespace(prefix, key_version)` builds the first two parts with ADR-0034's encoding (`analysis.cache_guard.versioned_key`, re-implemented because `adapters` may import only `ports` and `contracts`). The key version is the pipeline's `[pipeline.cache] key_schema_version`, so a store serves one version; bumping it starts from an empty namespace and leaves old entries unread.
3. **No Redis import at module level; secrets from the environment only.** `redis_client(host, port, db)` imports `redis` lazily and raises a clear error without the package. The password, if any, comes only from `METIS_REDIS_PASSWORD` in the process environment: never from `config/` or `.env`, and never in an error message.
4. **A machine-local `[cache]` section** (agent). `Settings.cache` (`store = "memory" | "redis"`, `redis_host`, `redis_port`, `redis_db`, `redis_namespace`), default `"memory"`, added to `HASH_EXCLUDED_SECTIONS`: where entries live does not change a result, as for `[events] sink` (ADR-0033). The default lives in the model; `config/defaults.toml` is not edited.
5. **Only the demo chat uses the switch** (agent). `wiring.from_settings.cache_store` builds the store, and `ChatSession` builds it once per session and keeps it across rebuilds. Experiment runs and the walking skeleton keep a fresh `InMemoryCacheStore` per run, so a replay never reads entries from another run.
6. **What a Redis hit shows.** A demo hit read from Redis demonstrates the answer-cache adapter only. It is not evidence of retrieval-cache savings (R-B1 is an offline replay and stores nothing in Redis) and not evidence that cross-user reuse is safe (K-1 reviews correctness; the demo bot-level scope is a placeholder, ADR-0023).
7. **Live test opt-in by availability, no new marker.** `tests/integration/test_redis_store_live.py` skips unless `redis` imports and the configured server answers a ping. The `services` extra, marker and Compose service are T-0/T-4's; the patch for them is in `docs/experiments/pipeline_b_interim_contracts_day3.md`.

## Alternatives considered
- **Key by each entry's own `key_schema_version`.** `get` receives only the fingerprint, so a lookup could not find the entry without a second index key. Rejected for one store per key version (point 2).
- **Expire entries in Redis (`EX`/`PX`).** Moves a validity rule into the store and makes the two stores behave differently. Rejected (ADR-0011 point 5).
- **Pickle or a Redis hash per field.** Pickle is unsafe to load and not the contract's form; a hash per field duplicates the contract. Rejected for the contract JSON.
- **The switch under `[pipeline.cache]`.** That section is policy and part of the config hash, so changing the store would change every run's hash. Rejected (point 4).
- **Redis for experiment replays too.** Shared state across runs breaks replay isolation and reproducibility (QA-REPRO). Rejected (point 5).
- **Add a `redis` extra and the `services` marker now.** `pyproject.toml` and the locks belong to T-0. Rejected; patch written instead (point 7).

## Consequences
- The default install and every default test need neither the package nor a server. The live check has not been run (no package, no server on the development machine, 2026-11-02).
- One shared contract test runs against both stores (`test_same_behaviour_as_in_memory_store`), so a third store has a ready check.
- Old-version entries stay in Redis after a key-schema bump until an operator removes them; the store never deletes.
- T-0's planned `test_redis_imported_only_in_redis_store` holds already: the only `import redis` is inside `redis_store.redis_client`.
- Guarding tests: `tests/unit/adapters/test_redis_store.py` (`test_put_then_get_round_trips_a_cache_entry`, `test_missing_key_returns_none`, `test_put_replaces_previous_entry`, `test_store_applies_no_ttl_or_validity_rules`, `test_keys_are_namespaced_by_key_version`, `test_store_module_imports_no_redis_library`, `test_redis_factory_raises_clear_error_when_package_missing`, `test_password_comes_only_from_the_environment_and_never_in_errors`, `test_default_cache_store_is_memory_and_changes_nothing_else`, `test_redis_switch_builds_a_redis_store_namespaced_by_the_key_version`, `test_chat_session_uses_the_configured_store`), `tests/unit/adapters/test_cache_store_contract.py` (`test_store_contract`, `test_same_behaviour_as_in_memory_store`), `tests/integration/test_redis_store_live.py` (opt-in).
