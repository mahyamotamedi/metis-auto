## Persian-first requirements (apply across all stages; spec §0 is the source)
- **Do not modify production routing or caching behavior.** The normalizer, language classifier and length buckets are new pure components used by evaluation code. - **No invented numbers.** Every threshold, minimum n, quota, floor, bucket boundary, agreement threshold, calibration-set size and δ is a config value read from `config/`. If a value has no decided default, the code must treat "unset" explicitly (result says "not evaluated" or "insufficient", never silently uses a number). List each unset value in your stage report as an open decision. Never write a claim of statistical reliability, validity or guarantee that the code cannot back with a reported n and interval.
- **Provenance labels** on every reported number: `measured`, `estimated`, or `simulated`, carried through result contracts and report tables.

- **Sampling vs weighting** are separate: allocation (what is drawn, may oversample minority languages) and weights (inverse selection probability for population-level totals) are both stored and never conflated.
- Tests are required for: normalization, language classification, sampling (allocation, weights, determinism, quota-unmet handling), and reporting (labels, insufficient-n handling, provenance). Use synthetic strings only, marked `[SYNTHETIC]`.

**Stage E1: baselines and metrics core (pure domain).**
- Baseline set as configuration: as-logged (mandatory), premium, cheapest-acceptable, oracle (hindsight, from a score matrix), random router with the candidate's model mix. Oracle takes ties to the cheapest model and carries a noise margin option (spec §1, §8 pitfall 7).
- Metrics as pure functions with tests: cost–quality Pareto points, quality at matched cost and cost at matched quality (CPT-style), PGR/APGR-style recovery with the near-zero-gap guard, oracle-headroom captured, non-inferiority against a configurable δ (no default value chosen; δ missing means "not evaluated", Q-13).
- Paired statistics: paired bootstrap over requests and **cluster bootstrap by session**, seeded; per-stratum minimum-n rule (n < configured minimum → "insufficient", pooled, never ranked); Holm or FDR option for multi-stratum claims.
- Every metric function takes a language slice and returns n, interval and a sufficiency label; Persian-only is the primary slice and English and mixed are separate; a slice below the configured minimum n (unset minimum means "insufficient" and says why) is never ranked or called significant.
- Exit: golden tests against hand-computed small examples; a test that a stratum under the minimum n is never ranked; a test that unset δ and unset minimum n produce "not evaluated" / "insufficient".
