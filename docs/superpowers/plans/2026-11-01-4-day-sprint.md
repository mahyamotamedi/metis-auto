# Metis-Auto 4-Day Sprint Implementation Plan

> **SUPERSEDED** by [`2026-11-01-final-plan.md`](2026-11-01-final-plan.md). Kept for history; do not follow.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each of the three people runs their own tasks in their own session; tasks never share files.

**Goal:** In 4 days, three people each build one end-to-end saving pipeline (cache → context → routing) on the full dataset, compare the three versions of every step with one command, combine the winners, and present the result with a working demo.

**Architecture:** Full-data experiments are pandas replays over `requests.parquet` from the existing EDA (`src/metis_auto/analysis/`), not over the sample-only experiment runner. Every step version is a small function from a requests frame to a modified frame; one `combine` function applies cache, then context, then routing, and one content-free `LeverResult` JSON per version feeds the comparison, the savings waterfall and the demo. Candidate code lives in `experiments/` until promoted (ADR-0009, ADR-0022).

**Tech Stack:** Python 3.13 (`.venv`), pandas/pyarrow (already used by `analysis/`), pytest, ruff, Streamlit (existing demo). A reranker/embedding model on a local GPU only if the licence question allows it (Task R-A2). No other new dependency without an ADR.

**Spec:** [`Metis-Auto Master Plan.pdf`](Metis-Auto%20Master%20Plan.pdf) (Nov 1, 2026, @Mahya), Parts 2–4; evidence from [`docs/full_eda/`](../../full_eda/) (on `origin/main`, PR #6) and its claims ledger `reports/full_eda/tables/claims_ledger.csv`. Supersedes parts of [`2026-11-01-phase-0-foundation.md`](2026-11-01-phase-0-foundation.md) (see "Reconciliation").

## One-page summary (slide)

- **What we build:** three competing pipelines, one per person. Each = one cache version + one context version + one routing version, chosen by config. Winners per step are combined.
- **Where the money is (EDA, observed):** per-call fees 37.6% of recorded cost, input tokens 36.0%, output 14.3%. One model label (`gemini-2.5-flash`) is 65.0% of cost. Retrieval is the biggest lever, so caching and context come first.
- **What we can prove in 4 days:** token and fee savings by replay on logs (simulation), with session-clustered intervals. **What we cannot:** answer quality, cache hit correctness, routing quality, net savings after overhead. We say so on a slide.
- **Budget:** owner says 100 USD. Until the ADR-0018 amendment is committed, the code limit is still 10 USD. Paid work is an optional branch (Day 2–3), gated by three things: the amendment, a licence answer about sending data to model APIs, and per-run approval.
- **Judging:** engineering quality first (layers, contracts, ADRs, tests, traceability, privacy), savings second, demo ("productish") throughout.
- **Schedule:** Day 1 shared base + first numbers. Day 2 cache + context. Day 3 routing + integration + dashboard. Day 4 final numbers, **code freeze at noon**, rehearsal, present.

## Global Constraints

- Agents never run `git commit`, `git push`, or history-rewriting commands. Humans commit. Every task ends with a changed-files list and a suggested message (CLAUDE.md § Git).
- No message content, instructions, retrieved text, bot IDs, user IDs or content hashes in anything committed (licence: use limited to education, no redistribution; EDA report §2). Committed outputs are aggregates; demo screens show ranks like `bot-07`, never IDs or text.
- Derived tables (`data/derived/`, `data/full_data/`) are git-ignored and local. Each person regenerates them with `scripts/full_eda_ingest.py` (pinned revision `30f578f283b903cdbd06cd1b5f7f962f76452ded`).
- `.env` is never read, printed or committed. The leaked Hugging Face token must be rotated by its owner before Day 1 (EDA report §7).
- Money: lifetime ceiling is set only in `config/defaults.toml` (`lifetime_ceiling = "20"`, `lifetime_cap = "10"`, `run_cap = "1"`); raising it needs a reviewed commit and a new ADR-0018 amendment. The ledger is per machine, so three machines have three ledgers. No live call unless an owner asks for it in chat; sample conversations need per-run approval (ADR-0018 point 5).
- Every design element cites an `FR-`/`QA-`/`NG-` or `H-n`/`X-n` ID. New decision → ADR. New dependency → ADR and regenerated locks. Tests run offline; layer rules in `tests/architecture` must pass; `docs/architecture/module_reference.md` rows updated with code.
- Evidence labels follow the EDA: *observed*, *metadata-derived*, *heuristic*, *hypothetical reconstruction*, *simulation*. A cache hit is a **candidate** hit until correctness is measured. Recorded cost is in unstated units; never mix it with repriced cost.
- Workflow bots (29.7% of requests, empty billing) are excluded from every hit rate and saving; "unknown" is never zero.
- Time split: tune March–July, report August–October (Master Plan Part 3). Timestamps are naive (Q-06): state that on every time-based result.
- Persian text: use `analysis/text_features.normalize_safe` (ZWNJ, Arabic yeh/kaf) for every key; do not invent a second normaliser.
- Windows (Saba) and macOS (Mahya, Kimia): commands in this plan show the macOS form `.venv/bin/python`; Windows uses `.venv\Scripts\python.exe`. Known pre-existing Windows failures (33 failed, 3 collection errors; `fcntl`, POSIX paths) are recorded as a baseline in Task S-0, not fixed.

## Review Focus

Failure modes the plan implies but no step would otherwise test, most likely first:

1. **Overlapping savings counted twice** (a cache hit also counted as a context saving): the combined saving must be less than the sum, and cache-served requests must get zero context/routing saving. → Task S-1.
2. **Leakage across the time split or across a session** (tune and report share a session or a duplicate prompt): splits are by whole session and duplicate family. → Task S-3.
3. **Cached-token convention** (`inputTokens` excludes cached tokens for five models; the EDA adds them back): repricing must use the same convention or routing savings are wrong. → Task R-A3.
4. **Repeated chunk with changed text** (same chunk ID, different content after a corpus update): reuse of cached retrieval or "drop with pointer" must not count it as safe when the chunk text hash differs. → Tasks R-B1, R-B2.
5. **A bot or request with too few rows** (one request, no turn 2): every per-bot figure says `insufficient`, never a number. → Task S-3.

## The three pipelines (read a row across; a column is one step's competing versions)

| Step | Pipeline A | Pipeline B | Pipeline C |
|---|---|---|---|
| Cache | popular-question cache (nightly, 90-day window, ≥3 occurrences in ≥2 sessions) | retrieval-result cache (bot + normalised query → chunk-ID set) | session memo + greeting skip gate |
| Context | reranker + relevance threshold (curve on a sample) | cross-turn chunk policy (drop repeats with a pointer) | history budget (stepped window) |
| Routing | per-bot reassignment + rules | kNN router | small classifier |

**Who is A, B, C is decided in the first hour of Day 1** (team decision). Suggested by fit: B = whoever owns `cache_replay` (Kimia); A = whoever owns routing/accounting; C = the third. Pipeline files are named by version, not person, so the choice costs nothing.

**Routing B and C without labels (default).** kNN and classifier need "was the cheap model good enough" labels, which only the paid benchmark can give. Without it: **B = nearest-profile policy** (for a request's feature profile, pick the cheapest model that bots with the nearest profiles already run in production), **C = a threshold classifier on the EDA's transparent rule features** (short, no RAG, no attachments, no tools, no JSON; EDA §4.4). Both are cost simulations; quality is "not proven". With the paid branch (Task P-1…P-3) they train on the benchmark labels instead, with wide intervals because n is small.

## Shared base interfaces (defined once, in S-1/S-2; every version consumes them)

- `requests` frame: the existing `analysis/requests_table.build_requests` output. Columns used by the sprint (verify names on Day 1 against `data_dictionary.md`; rename here if they differ): per-request recorded cost per block (`fees`, `input`, `output`, `cached`), `input_tokens`, `output_tokens`, `cached_tokens`, `bot` (opaque), `session`, `turn`, `t_arrive`, `t_done`, `period`, `llm_request`.
- `StepVersion` (Protocol, in `src/metis_auto/analysis/levers.py`): `name: str`, `step: Literal["cache","context","routing"]`, `apply(req: pd.DataFrame, ctx: ReplayContext) -> pd.DataFrame`. `apply` returns a copy with the same index; a cache version sets `served_from_cache=True` and zeroes all cost blocks on hit rows; a context version lowers `input_tokens` and the `input` block; a routing version replaces the model label and re-prices tokens.
- `ReplayContext` (frozen dataclass): `period_bounds`, `price_table` (loaded from `config/reference/`), `seed: int`, `min_n: int | None`.
- `combine(req, cache: StepVersion, context: StepVersion, routing: StepVersion, ctx) -> pd.DataFrame`: applies the three in this order; requests with `served_from_cache` are not passed to context or routing.
- `LeverResult` (frozen pydantic model in `src/metis_auto/analysis/lever_result.py`, fields all privacy-classified like `contracts`): `lever_id`, `step`, `version`, `n_requests`, `n_eligible`, `baseline_cost: dict[block, Decimal]`, `saving: dict[block, Decimal]`, `ci_low`, `ci_high` (session-clustered, from `analysis.stats.cluster_bootstrap_ratio`), `evidence_class`, `correctness_state` (`"unmeasured"` unless measured), `assumptions: tuple[str, ...]`, `overhead_ms: float | None`. JSON written to `reports/levers/<lever_id>.json`; no field can hold text (tested).
